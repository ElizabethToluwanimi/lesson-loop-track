⚠️ IMPORTANT: AMBIGUITIES & TECHNICAL DECISIONS BEFORE CODING

There are a few things I would not leave for the developer to guess.

1. Is this only for Arete Academia students?

Recommended decision: Build it as a multi-course platform under Arete Academia.

Don't hardcode the app to "Data Analysis Course." The system should allow you to add future courses such as:

Cybersecurity

AI

Digital Marketing

Data Science

Python

Business Analytics

2. Should students download everything?

Recommended: Admin decides whether each resource is:

View only

Downloadable

Both

This prevents sensitive course materials from automatically being downloadable.

3. How should progress be calculated?

Recommended:

Completed lessons ÷ Total lessons × 100

This makes progress transparent and easy to understand.

4. What counts as "learning"?

This is important for reminders.

Recommended: A learning session should count when a student performs meaningful activity such as:

Opening a lesson

Watching a lesson

Completing a lesson

Completing an assignment

Simply opening the app shouldn't automatically count as learning.

5. How should reminders work?

Recommended:

Students choose their preferred reminder time during onboarding.

The system checks whether they have learned that day before sending the reminder.

6. Should videos be hosted inside the app?

Recommended for MVP: Use cloud video hosting rather than storing large video files directly on the application server.

7. Should the app have AI from day one?

Recommended: NO.

First launch the learning platform, validate student usage, then introduce the AI tutor once you understand what students struggle with.

8. Biggest technical risk

Notification reliability is one of the most important areas to test.

The system should have a proper scheduled notification architecture rather than relying on the student's phone simply opening the app.
